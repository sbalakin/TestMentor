# Модель данных системы

## Общие принципы хранения данных

### Технология хранения (первая версия)
- **LocalStorage** браузера
- JSON формат для сериализации
- Ключи хранилища:
  - `mentors` - массив всех менторов
  - `work_records` - массив всех записей о работе
  - `reports` - массив всех сформированных актов
  - `settings` - настройки системы
  - `categories` - категории услуг

### Принципы работы с данными
- Автоматическое сохранение после каждого изменения
- Валидация данных перед сохранением
- Генерация уникальных ID для каждой сущности
- Мягкое удаление для критичных данных (опционально)

## Сущность 1: Ментор (Mentor)

### Описание
Основная сущность системы, представляющая специалиста, оказывающего услуги.

### Структура данных

```json
{
  "id": "unique_id_string",
  "personal_info": {
    "full_name": "Иванов Иван Иванович",
    "email": "ivanov@example.com",
    "phone": "+7 (999) 123-45-67",
    "photo_url": "path/to/photo.jpg или null"
  },
  "professional_info": {
    "specialization": "Разработка ботов",
    "hourly_rate": 1000,
    "start_date": "2025-01-15",
    "status": "active"
  },
  "documents": {
    "passport_or_inn": "1234 567890",
    "bank_details": "Р/с: 40817..., БИК: 044525..., Банк: Сбербанк"
  },
  "additional": {
    "notes": "Специализируется на Telegram-ботах",
    "tags": ["python", "telegram", "api"]
  },
  "metadata": {
    "created_at": "2025-09-01T10:00:00Z",
    "updated_at": "2025-09-15T14:30:00Z",
    "created_by": "admin"
  }
}
```

### Поля

| Поле | Тип | Обязательное | Описание | Валидация |
|------|-----|--------------|----------|-----------|
| `id` | string | Да | Уникальный идентификатор | UUID v4 или timestamp |
| `personal_info.full_name` | string | Да | ФИО ментора | Мин. 2 слова, макс. 100 символов |
| `personal_info.email` | string | Да | Email адрес | Валидный email, уникальный |
| `personal_info.phone` | string | Нет | Номер телефона | Формат +7 (XXX) XXX-XX-XX |
| `personal_info.photo_url` | string\|null | Нет | URL или path к фото | - |
| `professional_info.specialization` | string | Да | Специализация | Из списка или "Другое" |
| `professional_info.hourly_rate` | number | Да | Ставка за час (руб.) | > 0, макс. 100000 |
| `professional_info.start_date` | string | Да | Дата начала работы | ISO 8601, не в будущем |
| `professional_info.status` | string | Да | Статус | "active" или "inactive" |
| `documents.passport_or_inn` | string | Нет | Паспорт или ИНН | - |
| `documents.bank_details` | string | Нет | Банковские реквизиты | - |
| `additional.notes` | string | Нет | Дополнительные заметки | Макс. 1000 символов |
| `additional.tags` | array | Нет | Теги для поиска | - |
| `metadata.created_at` | string | Да (авто) | Дата создания | ISO 8601 |
| `metadata.updated_at` | string | Да (авто) | Дата обновления | ISO 8601 |
| `metadata.created_by` | string | Нет | Кто создал | - |

### Индексы для поиска
- Поиск по `email` (уникальный)
- Поиск по `full_name`
- Фильтр по `status`
- Фильтр по `specialization`

### Вычисляемые поля (не хранятся, рассчитываются на лету)
- `total_hours` - общее количество отработанных часов
- `total_earned` - общая сумма заработка
- `hours_this_month` - часов в текущем месяце
- `earned_this_month` - заработок за текущий месяц
- `average_hours_per_month` - среднее количество часов в месяц
- `last_activity_date` - дата последней записи о работе

### Связи с другими сущностями
- Один ко многим: `Mentor → WorkRecord`
- Один ко многим: `Mentor → Report`

## Сущность 2: Запись о работе (WorkRecord)

### Описание
Информация о выполненной работе ментором за определенный период.

### Структура данных

```json
{
  "id": "unique_id_string",
  "mentor_id": "mentor_unique_id",
  "work_details": {
    "date": "2025-09-15",
    "hours": 8.0,
    "type": "Разработка",
    "project": "Telegram-бот поддержки",
    "description": "Разработка основного функционала бота: обработка команд, интеграция с API"
  },
  "financial": {
    "hourly_rate": 1000,
    "total_amount": 8000,
    "is_paid": false,
    "payment_date": null
  },
  "additional": {
    "notes": "Требуется дополнительная оптимизация",
    "included_in_reports": []
  },
  "metadata": {
    "created_at": "2025-09-15T18:00:00Z",
    "updated_at": "2025-09-15T18:00:00Z",
    "created_by": "admin"
  }
}
```

### Поля

| Поле | Тип | Обязательное | Описание | Валидация |
|------|-----|--------------|----------|-----------|
| `id` | string | Да | Уникальный идентификатор | UUID v4 или timestamp |
| `mentor_id` | string | Да | ID ментора | Должен существовать |
| `work_details.date` | string | Да | Дата выполнения работы | ISO 8601 (YYYY-MM-DD), не в будущем |
| `work_details.hours` | number | Да | Количество часов | > 0, макс. 24, шаг 0.5 |
| `work_details.type` | string | Да | Тип работы | Из справочника категорий |
| `work_details.project` | string | Нет | Название проекта/задачи | Макс. 200 символов |
| `work_details.description` | string | Да | Описание работы | Мин. 10, макс. 2000 символов |
| `financial.hourly_rate` | number | Да | Ставка за час | > 0, копируется из профиля ментора |
| `financial.total_amount` | number | Да | Общая сумма | Авто: hours × hourly_rate |
| `financial.is_paid` | boolean | Да | Оплачено или нет | По умолчанию false |
| `financial.payment_date` | string\|null | Нет | Дата оплаты | ISO 8601 или null |
| `additional.notes` | string | Нет | Внутренние заметки | Макс. 500 символов |
| `additional.included_in_reports` | array | Да | Массив ID актов | Пустой массив по умолчанию |
| `metadata.created_at` | string | Да (авто) | Дата создания записи | ISO 8601 |
| `metadata.updated_at` | string | Да (авто) | Дата обновления | ISO 8601 |
| `metadata.created_by` | string | Нет | Кто создал запись | - |

### Индексы для поиска
- Поиск по `mentor_id`
- Фильтр по `date` (диапазон)
- Фильтр по `type`
- Фильтр по `is_paid`
- Фильтр по `project`

### Вычисляемые поля
- `mentor_name` - ФИО ментора (join с Mentor)
- `is_included_in_report` - boolean, входит ли в хотя бы один акт

### Бизнес-правила
- При изменении количества часов или ставки автоматически пересчитывается `total_amount`
- Нельзя удалить запись, включенную в акт (или мягкое удаление)
- При удалении ментора все его записи также удаляются (или помечаются как orphan)
- Дата работы не может быть позже текущей даты

### Связи с другими сущностями
- Многие к одному: `WorkRecord → Mentor`
- Многие ко многим: `WorkRecord ↔ Report` (через `included_in_reports`)

## Сущность 3: Акт выполненных работ (Report)

### Описание
Официальный документ, формируемый на основе записей о работе за определенный период.

### Структура данных

```json
{
  "id": "unique_id_string",
  "report_info": {
    "number": "№47/09-2025",
    "date": "2025-09-30",
    "period_from": "2025-09-01",
    "period_to": "2025-09-30"
  },
  "parties": {
    "customer": {
      "name": "ООО 'Компания'",
      "inn": "1234567890",
      "ogrn": "1234567890123",
      "address": "г. Москва, ул. Примерная, д. 1",
      "representative_position": "Директор",
      "representative_name": "Петров П.П."
    },
    "executor": {
      "mentor_id": "mentor_unique_id",
      "full_name": "Иванов Иван Иванович",
      "passport_or_inn": "1234 567890",
      "address": "г. Москва, ул. Ленина, д. 10",
      "phone": "+7 (999) 123-45-67",
      "email": "ivanov@example.com"
    }
  },
  "work_records": [
    {
      "work_record_id": "work_record_id_1",
      "date": "2025-09-01",
      "description": "Разработка функционала",
      "hours": 8.0,
      "hourly_rate": 1000,
      "amount": 8000
    }
  ],
  "totals": {
    "total_hours": 80.0,
    "total_amount": 80000,
    "amount_in_words": "Восемьдесят тысяч рублей 00 копеек"
  },
  "file_info": {
    "pdf_filename": "Akt_Ivanov_09-2025_30.09.2025.pdf",
    "pdf_path": "reports/2025/09/",
    "file_size": 245678
  },
  "metadata": {
    "created_at": "2025-09-30T16:00:00Z",
    "created_by": "admin",
    "status": "generated"
  }
}
```

### Поля

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| `id` | string | Да | Уникальный идентификатор |
| `report_info.number` | string | Да | Номер акта |
| `report_info.date` | string | Да | Дата составления акта |
| `report_info.period_from` | string | Да | Начало периода |
| `report_info.period_to` | string | Да | Конец периода |
| `parties.customer.*` | object | Да | Данные заказчика |
| `parties.executor.*` | object | Да | Данные исполнителя (ментора) |
| `work_records` | array | Да | Массив включенных записей о работе |
| `work_records[].work_record_id` | string | Да | ID исходной записи о работе |
| `work_records[].date` | string | Да | Дата работы |
| `work_records[].description` | string | Да | Описание работы |
| `work_records[].hours` | number | Да | Количество часов |
| `work_records[].hourly_rate` | number | Да | Ставка |
| `work_records[].amount` | number | Да | Сумма |
| `totals.total_hours` | number | Да (авто) | Общее количество часов |
| `totals.total_amount` | number | Да (авто) | Общая сумма |
| `totals.amount_in_words` | string | Да (авто) | Сумма прописью |
| `file_info.pdf_filename` | string | Да | Имя файла PDF |
| `file_info.pdf_path` | string | Нет | Путь к файлу |
| `file_info.file_size` | number | Нет | Размер файла в байтах |
| `metadata.created_at` | string | Да | Дата создания |
| `metadata.created_by` | string | Нет | Кто создал |
| `metadata.status` | string | Да | Статус: "draft", "generated" |

### Индексы для поиска
- Поиск по `parties.executor.mentor_id`
- Фильтр по периоду (`period_from`, `period_to`)
- Фильтр по дате создания (`created_at`)
- Поиск по номеру акта (`number`)

### Вычисляемые поля
- `work_records_count` - количество включенных записей
- `mentor_name` - ФИО ментора

### Бизнес-правила
- Нельзя изменить акт после генерации (immutable)
- При удалении акта записи о работе остаются, но из их `included_in_reports` удаляется ID акта
- Автоматический расчет totals на основе work_records
- Автоматическая генерация номера акта по шаблону
- Сумма прописью генерируется автоматически на русском языке

### Связи с другими сущностями
- Многие к одному: `Report → Mentor`
- Многие ко многим: `Report ↔ WorkRecord`

## Валидация и целостность данных

### Правила валидации при сохранении
1. Все обязательные поля должны быть заполнены
2. Email должен быть уникальным для менторов
3. Ставка и количество часов должны быть положительными числами
4. Даты должны быть в корректном формате ISO 8601
5. Ссылки на другие сущности (FK) должны существовать

### Проверка целостности при удалении
- При удалении ментора: каскадное удаление или запрет, если есть связанные данные
- При удалении записи о работе: удаление ссылки из актов
- При удалении акта: обновление связанных записей о работах

### Автоматические действия
- Генерация ID при создании новой записи
- Установка timestamp при создании и обновлении
- Автоматический расчет сумм
- Пересчет статистики после изменений

## Производительность и оптимизация

### Рекомендации по LocalStorage
- Лимит: ~5-10 МБ (зависит от браузера)
- Периодическая очистка старых/неактуальных данных
- Возможность архивирования старых записей
- Экспорт данных при достижении лимита

### Индексирование для быстрого поиска
- Создание in-memory индексов после загрузки данных
- Использование Map/Set для быстрого доступа по ID
- Кеширование часто используемых вычислений

### Будущее масштабирование (при переходе на backend)
- Использование реляционной БД (PostgreSQL)
- Индексы на внешние ключи
- Полнотекстовый поиск
- Партиционирование таблиц по датам
