# Бизнес-логика и сценарии использования

## 1. Основные бизнес-правила

### 1.1. Правила работы с менторами

**Создание ментора**
- Email должен быть уникальным в системе
- Нельзя создать ментора без обязательных полей (ФИО, email, специализация, ставка)
- Ставка должна быть больше 0
- Новый ментор по умолчанию получает статус "Активный"
- При создании автоматически генерируется уникальный ID

**Редактирование ментора**
- Изменение ставки не влияет на уже существующие записи о работе
- При изменении email проверяется уникальность
- Нельзя изменить ID ментора
- Автоматически обновляется поле "Дата последнего обновления"

**Удаление ментора**
- Если у ментора есть записи о работе - показать предупреждение
- Два варианта:
  - Изменить статус на "Неактивный" (рекомендуется)
  - Удалить полностью вместе со всеми записями (после подтверждения)
- Если ментор включен в акты - удаление недоступно, только деактивация

**Статус ментора**
- Активный: отображается во всех списках, можно добавлять работы
- Неактивный: отображается с фильтром, нельзя добавлять новые работы

---

### 1.2. Правила работы с записями о работе

**Добавление записи**
- Нельзя добавить работу на будущую дату
- Количество часов в день не может превышать 24
- Количество часов должно быть больше 0
- Ставка по умолчанию берется из профиля ментора, но может быть изменена для конкретной записи
- Сумма автоматически рассчитывается: Часы × Ставка
- Можно вручную изменить итоговую сумму (для случаев скидок/наценок)

**Редактирование записи**
- При изменении часов или ставки сумма автоматически пересчитывается
- Если запись включена в акт - показывать предупреждение при изменении
- Рекомендуется не редактировать записи, включенные в акты

**Удаление записи**
- Если запись включена в акт - показать предупреждение
- Требуется подтверждение удаления
- После удаления обновляется статистика ментора

**Статус оплаты**
- По умолчанию: "Не оплачено"
- Можно отметить как "Оплачено" с указанием даты оплаты
- Массовое изменение статуса для нескольких записей

---

### 1.3. Правила формирования актов

**Выбор периода**
- Можно выбрать месяц/год
- Можно указать произвольный диапазон дат
- Система автоматически находит все записи выбранного ментора за период

**Выбор работ**
- Все найденные записи по умолчанию включены в акт
- Можно исключить отдельные записи
- В акт должна быть включена минимум 1 запись

**Номер акта**
- Автоматическая генерация по шаблону из настроек
- Можно изменить вручную
- Рекомендуется уникальный номер (система предупреждает о дубликатах)

**Генерация акта**
- Акт формируется на основе данных ментора и выбранных записей о работе
- Данные заказчика берутся из настроек системы
- После генерации акт сохраняется в архив
- В записях о работе добавляется ссылка на акт
- Акт immutable - нельзя изменить после создания

**Расчеты в акте**
- Общее количество часов: сумма часов всех включенных записей
- Общая сумма: сумма всех сумм записей
- Сумма прописью: автоматическая конвертация числа в текст на русском языке

---

### 1.4. Правила статистики и аналитики

**Расчет показателей**
- Всего часов: сумма всех записей ментора
- Часов в месяце: сумма записей за текущий календарный месяц
- Всего заработано: сумма всех сумм записей
- К выплате за месяц: сумма за текущий месяц

**Фильтрация данных**
- По умолчанию показываются активные менторы
- Можно включить отображение неактивных
- Поиск работает по частичному совпадению
- Фильтры можно комбинировать

## 2. Сценарии использования

### Сценарий 1: Добавление нового ментора

**Актор**: Администратор

**Предусловия**: Пользователь находится на главной странице

**Основной поток**:
1. Администратор нажимает кнопку "Добавить ментора"
2. Система открывает страницу create-mentor.html
3. Администратор заполняет обязательные поля:
   - ФИО: "Иванов Иван Иванович"
   - Email: "ivanov@example.com"
   - Специализация: "Разработка ботов"
   - Ставка: "1500" руб/час
   - Дата начала: выбирает текущую дату
   - Статус: оставляет "Активный"
4. Администратор заполняет опциональные поля:
   - Телефон: "+7 (999) 123-45-67"
   - Паспортные данные: "1234 567890"
5. Система валидирует данные
6. Администратор нажимает кнопку "Сохранить"
7. Система:
   - Генерирует уникальный ID
   - Проверяет уникальность email
   - Сохраняет ментора в LocalStorage
   - Показывает уведомление "Ментор успешно добавлен"
   - Перенаправляет на страницу просмотра профиля ментора

**Альтернативные потоки**:

**A1: Email уже существует**
- На шаге 7: система обнаруживает дубликат email
- Показывает ошибку под полем email: "Этот email уже используется"
- Поле email подсвечивается красным
- Пользователь меняет email и повторяет попытку

**A2: Не заполнены обязательные поля**
- На шаге 6: система не позволяет нажать "Сохранить" (кнопка disabled)
- Незаполненные обязательные поля подсвечены красным
- Под полями показаны сообщения "Обязательное поле"

**A3: Сохранить и добавить еще**
- На шаге 6: администратор нажимает "Сохранить и добавить еще"
- Система сохраняет ментора
- Форма очищается
- Показывается уведомление об успехе
- Пользователь остается на странице создания

**Постусловия**: Новый ментор добавлен в систему и отображается в списке на главной странице

### Сценарий 2: Добавление записи о работе

**Актор**: Администратор

**Предусловия**: В системе есть хотя бы один ментор

**Основной поток**:
1. Администратор переходит на страницу add-work.html
   - Через главное меню "Добавить работу"
   - Или через кнопку на профиле ментора (тогда ментор предзаполнен)
2. Система отображает форму
3. Администратор выбирает ментора из списка (если не предзаполнено)
4. Система отображает текущую ставку ментора
5. Администратор заполняет данные:
   - Дата: "15.09.2025"
   - Часы: "8"
   - Тип работы: "Разработка"
   - Проект: "Telegram-бот поддержки"
   - Описание: "Разработка основного функционала бота"
6. Система автоматически рассчитывает сумму: 8 × 1500 = 12000 руб
7. Администратор нажимает "Сохранить"
8. Система:
   - Валидирует данные
   - Генерирует ID записи
   - Сохраняет в LocalStorage
   - Обновляет статистику ментора
   - Показывает уведомление "Запись добавлена"
   - Перенаправляет на view-works.html или профиль ментора

**Альтернативные потоки**:

**A1: Дата в будущем**
- На шаге 5: пользователь пытается выбрать будущую дату
- Система не позволяет выбрать дату позже текущей в календаре
- Показывает ошибку: "Дата не может быть в будущем"

**A2: Слишком много часов**
- На шаге 5: пользователь вводит 25 часов
- Система показывает ошибку: "Количество часов не может превышать 24"

**A3: Изменение ставки для конкретной работы**
- На шаге 5: администратор изменяет ставку вручную на 2000
- Система пересчитывает сумму: 8 × 2000 = 16000 руб
- Сохраняется с измененной ставкой

**A4: Копирование последней записи**
- На шаге 2: администратор нажимает "Копировать последнюю"
- Система заполняет форму данными последней записи этого ментора
- Пользователь меняет только дату и часы
- Сохраняет

**Постусловия**: Запись о работе добавлена, статистика ментора обновлена

### Сценарий 3: Формирование акта выполненных работ

**Актор**: Администратор

**Предусловия**: 
- В системе есть ментор
- У ментора есть записи о работе за нужный период
- Настройки заказчика заполнены

**Основной поток**:

**Шаг 1: Выбор параметров**
1. Администратор переходит на generate-report.html
   - Через меню "Архив актов" → "Создать акт"
   - Или через профиль ментора → "Сформировать акт"
2. Администратор выбирает:
   - Ментор: "Иванов Иван Иванович"
   - Период: "Сентябрь 2025"
3. Система автоматически генерирует номер акта: "№47/09-2025"
4. Дата составления: текущая дата (можно изменить)
5. Администратор нажимает "Далее"

**Шаг 2: Выбор работ**
6. Система находит все записи о работе:
   - Ментор: Иванов И.И.
   - Период: с 01.09.2025 по 30.09.2025
   - Находит 15 записей
7. Система отображает таблицу с записями, все чекбоксы отмечены
8. Система показывает сводку:
   - Записей: 15
   - Часов: 100
   - Сумма: 150 000 руб
9. Администратор просматривает список
10. (Опционально) Администратор снимает галочку с 1 записи
11. Система пересчитывает сводку:
    - Записей: 14
    - Часов: 92
    - Сумма: 138 000 руб
12. Администратор нажимает "Предпросмотр"

**Шаг 3: Предпросмотр и генерация**
13. Система отображает предпросмотр акта со всеми данными:
    - Номер и дата
    - Данные заказчика (из настроек)
    - Данные ментора
    - Таблица работ
    - Итоги
14. Администратор проверяет данные
15. Администратор нажимает "Скачать PDF"
16. Система:
    - Генерирует PDF документ
    - Сохраняет акт в архив (в LocalStorage)
    - Обновляет записи о работе (добавляет ID акта в included_in_reports)
    - Скачивает файл: "Akt_Ivanov_09-2025_30.09.2025.pdf"
    - Показывает уведомление "Акт успешно сформирован"
17. Система предлагает:
    - Сформировать еще один акт
    - Перейти в архив актов
    - Вернуться к профилю ментора

**Альтернативные потоки**:

**A1: Нет записей за выбранный период**
- На шаге 6: система не находит записей
- Показывает сообщение: "Нет записей о работе за выбранный период"
- Предлагает выбрать другой период или вернуться назад

**A2: Изменение номера акта**
- На шаге 3: администратор вручную меняет номер на "№50/09-2025"
- Система проверяет уникальность
- Если номер уже существует - показывает предупреждение (но не блокирует)

**A3: Редактирование выбора работ**
- На шаге 14: администратор нажимает "Редактировать"
- Возврат к шагу 2
- Можно изменить выбор записей

**A4: Печать акта**
- На шаге 15: администратор нажимает "Печать" вместо "Скачать PDF"
- Открывается диалог печати браузера
- Акт сохраняется в архив

**Постусловия**: 
- Акт сохранен в архив
- PDF файл скачан
- Записи о работе отмечены как включенные в акт

**Актор**: Администратор

**Предусловия**: В системе есть данные о менторах и их работе

**Основной поток**:

   - Сумма за месяц: 350 000 руб

   - К выплате за месяц
   - Статус
5. Администратор анализирует данные
6. (Опционально) Администратор использует фильтры:
   - Выбирает "Только активные"
   - Сортирует по "Часов в месяце" (по убыванию)

8. Администратор видит топ самых активных менторов

**A3: Экспорт данных**
- На шаге 5: администратор нажимает "Экспорт в Excel"
- Система генерирует Excel файл со всеми менторами и статистикой
- Файл скачивается

**Постусловия**: Администратор получил полную картину по работе менторов

**Актор**: Администратор

   - Валидирует данные

   - Показывает уведомление "Данные сохранены"

**A3: Изменение статуса на "Неактивный"**

## 3. Бизнес-процессы

### Процесс 1: Ежемесячная отчетность

**Описание**: В конце каждого месяца администратор формирует акты для всех менторов

**Шаги**:
1. Последний день месяца (например, 30 сентября)
2. Администратор открывает главную страницу
3. Проверяет список менторов и их статистику за месяц
4. Для каждого активного ментора:
   - Проверяет, есть ли работы за месяц
   - Если есть - нажимает "Сформировать акт"
   - Выбирает период: "Сентябрь 2025"
   - Проверяет список работ
   - Генерирует и скачивает PDF
5. Все акты сохраняются в папке
6. Акты отправляются менторам и в бухгалтерию
7. В системе отмечаются записи как "Оплачено" после перевода денег

**Оптимизация** (для будущих версий):
- Массовая генерация актов одной кнопкой
- Автоматическая отправка по email
- Напоминание за 2-3 дня до конца месяца

### Процесс 2: Прием нового ментора на проект

**Описание**: Подключение нового ментора к работе

**Шаги**:
1. Решение о привлечении ментора
2. Сбор информации:
   - ФИО, контакты
   - Специализация
   - Договоренность о ставке
   - Паспортные/реквизиты
3. Администратор создает профиль в системе
4. Согласование первой задачи
5. После выполнения - добавление первой записи о работе
6. Регулярное взаимодействие
7. В конце месяца - формирование первого акта

---

### Процесс 3: Завершение сотрудничества с ментором

**Описание**: Ментор больше не работает с компанией

**Шаги**:
1. Принятие решения о завершении сотрудничества
2. Сформировать финальный акт за последний период
3. Проверить, что все работы оплачены
4. Изменить статус ментора на "Неактивный"
5. Ментор остается в системе для истории, но:
   - Не отображается в активных списках
   - Нельзя добавить новую работу
   - Можно просмотреть историю и статистику

**Важно**: Не удалять ментора, чтобы сохранить историю

## 4. Валидация и ограничения

### Правила валидации форм

**Email**
- Формат: name@domain.com
- Уникальность в системе
- Обязательное поле

**Телефон**
- Формат: +7 (XXX) XXX-XX-XX
- Опциональное поле
- Автоформатирование при вводе

**Ставка**
- Тип: положительное число
- Минимум: 0.01
- Максимум: 100000
- Может быть дробным (например, 1500.50)

**Количество часов**
- Тип: положительное число
- Минимум: 0.5
- Максимум: 24 (за один день)
- Шаг: 0.5

**Дата**
- Формат: ISO 8601 (YYYY-MM-DD)
- Не может быть в будущем
- Может быть сегодня или в прошлом

**Описание работы**
- Минимум: 10 символов
- Максимум: 2000 символов
- Обязательное поле

## 5. Обработка ошибок

### Типы ошибок

**Ошибки валидации**
- Показываются под конкретным полем
- Цвет: красный
- Блокируется отправка формы

**Ошибки сохранения**
- Показываются в toast уведомлении
- Цвет: красный
- Текст: "Не удалось сохранить данные. Попробуйте еще раз."

**Ошибки загрузки**
- Показываются вместо данных
- Текст: "Ошибка загрузки данных"
- Кнопка "Попробовать снова"

**Критические ошибки**
- Переполнение LocalStorage
- Показать предупреждение
- Предложить экспортировать и очистить старые данные

## 6. Расчет суммы прописью

### Алгоритм

**Функция**: конвертация числа в текст на русском языке

**Примеры**:
- 1000 → "Одна тысяча рублей 00 копеек"
- 12345 → "Двенадцать тысяч триста сорок пять рублей 00 копеек"
- 150000 → "Сто пятьдесят тысяч рублей 00 копеек"

**Правила**:
- Правильное склонение: рубль/рубля/рублей
- Всегда "00 копеек" (копейки не используются)
- Первая буква заглавная

## 7. Политика хранения данных

### LocalStorage

**Ключи**:
- `mentors_db` - массив менторов
- `work_records_db` - массив записей
- `reports_db` - массив актов
- `settings_db` - настройки
- `categories_db` - категории

**Лимиты**:
- Приблизительно 5-10 МБ на домен
- Рекомендация: не более 1000 записей о работах
- При приближении к лимиту - предлагать экспорт и архивирование

**Backup**:
- Рекомендация делать резервную копию раз в месяц
- Экспорт в JSON файл
- Хранить локально или в облаке
